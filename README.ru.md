# testvariance

**Сравнивайте результаты CI при одинаковых условиях и проверяйте исходные свидетельства.**

[English](README.md) · [简体中文](README.zh-CN.md) · [Deutsch](README.de.md)

Автономная библиотека и CLI для истории тестов в каноническом JSONL. Группировка по тесту, ревизии и окружению позволяет видеть смешанные результаты, успешное восстановление после ошибки и измеренное время повторных попыток. Для работы нужна только стандартная библиотека Python 3.10+.

## Назначение

Успех после сбоя сам по себе не доказывает нестабильность теста: код или окружение могли измениться. testvariance не объединяет такие наблюдения, не запускает тесты повторно, не подключается к CI, не определяет причину сбоя и не изолирует тесты автоматически. [pytest-rerunfailures](https://github.com/pytest-dev/pytest-rerunfailures) повторно запускает pytest; [test-summary/action](https://github.com/test-summary/action) отображает отчёты в GitHub Actions. Этот независимый проект анализирует предоставленную историю локально, явно учитывая сопоставимость и отсутствующие измерения.

## Установка и пример

Публикация в индексе пакетов не предполагается. Выполните из каталога репозитория:

```sh
python -m pip install .
testvariance analyze examples/outcomes.jsonl --format text
testvariance analyze examples/outcomes.jsonl --format json
cat examples/outcomes.jsonl | testvariance analyze - --fail-on-mixed
```

Пример содержит 7 наблюдений, 4 сопоставимые группы и 1 группу со смешанными результатами. Последняя команда намеренно возвращает код 1. В смешанной группе частота сбоев равна 1/3, один запуск восстановился, измерено 2,5 секунды повторных попыток, у одной повторной попытки длительность неизвестна. Сбой другой ревизии учитывается отдельно. Без установки в POSIX shell: `PYTHONPATH=src python -m testvariance analyze examples/outcomes.jsonl`.

## Формат входа

Один JSON-объект в каждой непустой строке UTF-8:

```json
{"test_id":"suite/test","revision":"a1b2c3","environment":"linux-py312","run_id":"build-101","attempt":1,"outcome":"fail","duration_seconds":12.5}
```

- Обязательны `test_id`, `revision`, `environment`, `run_id`, `attempt`, `outcome`.
- Четыре идентификатора — строки до 4096 символов, не состоящие только из пробелов. Регистр и пробелы сохраняются, нормализации нет. Используйте полный идентификатор коммита и включайте платформу, зависимости и конфигурацию в идентификатор окружения.
- `attempt` — положительное целое число, не логическое значение. Это исходный номер попытки данного теста, ревизии, окружения и запуска, а не номер строки.
- `outcome`: только `pass`, `fail`, `error` или `skip`.
- Необязательное `duration_seconds`: конечное неотрицательное число либо `null`. Отсутствие/null означает неизвестную длительность, 0 — измеренный ноль.
- Неизвестные поля, повторяющиеся JSON-поля, некорректный UTF-8, NaN/Infinity и повторные ключи наблюдений запрещены. Ключ: `(test_id, revision, environment, run_id, attempt)`. Даже полностью одинаковые дубликаты отклоняются.
- Ограничения: 32 MiB на вход, 64 KiB на физическую строку вместе с переводом строки, 100000 наблюдений. Пустые строки входят в байтовый лимит; пустой файл допустим; UTF-8 BOM не принимается. Суммарная длительность также должна оставаться конечной.

Импорта JUnit/XML пока нет. Преобразуйте отчёты заранее, сохраняя достоверные метаданные и номера попыток; не угадывайте ревизию или окружение по имени файла.

## Значение отчёта

По умолчанию выводится JSON с `schema_version: 1`. Группы сортируются по трём идентификаторам, запуски — по `run_id`, попытки — по номеру только внутри своего запуска. Порядок входных строк не влияет на результат. Идентификаторы запусков не трактуются как временная шкала.

- `counts` — число наблюдений каждого исхода; `executed_attempts` исключает skip.
- `failure_frequency = (fail + error) / (pass + fail + error)` — наблюдаемая частота, взвешенная по попыткам, а не вероятность сбоя сборки. Если все попытки пропущены, значение null.
- `failure_frequency_wilson_95` — номинальный 95%-й интервал Уилсона; при отсутствии выполненных попыток — null. Повторы часто зависимы и выборочны, поэтому реальное покрытие не обязательно составляет 95%. Это описательная статистика, а не гарантия и не уверенность в нестабильности.
- `mixed_outcomes` означает наличие pass и fail/error в одной сопоставимой группе, возможно в разных запусках. Это свидетельство различий, не доказательство недетерминизма или причины сбоя.
- `recovered_runs` учитывает запуски, где последняя наблюдаемая попытка — pass, а ранее был fail/error. pass→fail и fail→pass→skip не считаются восстановлением. «Последняя» означает максимальный предоставленный номер, а не подтверждённое завершение CI.
- `observed_retry_seconds` — сумма известных длительностей предоставленных попыток с номером больше 1, включая skip с измеренной длительностью. `retry_missing_duration_count` — число таких повторов без длительности.
- `missing_attempt_count` каждого запуска — количество отсутствующих номеров от 1 до максимального предоставленного. Их стоимость не оценивается. Сумма времени выполнения не равна задержке по часам или денежным расходам.
- `observed_duration_seconds` и `missing_duration_count` относятся ко всем предоставленным попыткам. Нулевая сумма при неизвестных длительностях не доказывает нулевые затраты.

Отчёт содержит исходные идентификаторы и требует соответствующей защиты. Инструмент не обращается к сети и не собирает stdout, сообщения ошибок, трассировки или переменные окружения. Управляющие символы экранируются в текстовом отчёте; ошибки проверки не повторяют исходные данные. Идентификаторы в отчёте не анонимизируются.

## Коды возврата и библиотека

0 — корректный отчёт. 1 — только если явно задан `--fail-on-mixed` и найдена смешанная группа; полный отчёт сохраняется в stdout. 2 — неправильные данные, аргументы или ошибка ввода-вывода. Некорректный вход не создаёт частичный отчёт. Включайте такой порог только осознанно: это не автоматический вердикт о нестабильности.

```python
from testvariance import analyze, load_jsonl
with open("examples/outcomes.jsonl", "rb") as source:
    report = analyze(load_jsonl(source))
print(report["mixed_group_count"])
```

`Observation` проверяет данные при создании, `analyze` также отклоняет дубликаты. `InputError` наследует `ValueError`. Данные хранятся в памяти в указанных пределах; библиотека не записывает файлы и не изменяет наблюдения.
